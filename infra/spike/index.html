LiveKit WebRTC spike

The day-1 gate. This publishes a mic track to a self-hosted LiveKit server and subscribes to it back. If the ICE state reaches connected and audio levels move when you speak, WebRTC works through Docker on this machine and the rest of the voice feature is ordinary engineering.

If it hangs at checking, LiveKit is advertising an IP the browser cannot reach. Check rtc.node_ip and rtc.use_external_ip in infra/livekit.yaml. The TCP fallback on 7881 is the safety net.

The tone button needs no microphone permission, so it runs headlessly and in CI. It exercises the same publisher peer connection and the same ICE negotiation - which is the part that actually fails through Docker.
